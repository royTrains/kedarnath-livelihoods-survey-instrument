# Rebuild plan — 2026-10-05

Governing rule, from the user: **the 7 interviews already collected on build `4b87e5`
must stay interpretable.** So:

1. A variable whose MEANING changes gets a NEW NAME. Never reuse a name for a different quantity.
2. A variable that is only REWORDED or MOVED keeps its name.
3. A variable that gains a response CODE keeps its name, and the conflation in the old
   data is documented in RETIRED/MIGRATION below.
4. A removed variable is recorded in RETIRED with its last build, so the sheet column
   remains readable. Columns are NOT deleted from the sheet.
5. `checks/14_sheet_vs_dictionary.py` enforces 1-4 against the live export header.

## Answers settled this round

- **D11 target_occ** — KEPT, reworded from the counterfactual ("if you could not continue")
  to forward-looking aspiration ("what work do you want to move to in the next few years").
  Becomes an aspiration measure, not a displacement destination; the skill-distance
  anchor survives but must be written up as stated intent, not revealed alternative.
- **D16 income volatility** — NO new questions. `income_seasonality_cv`'s fallback path
  is already a closed-form CV of the two-level series implied by annual total x Yatra
  share x Yatra months (02_build_final_dataset.do:316-319). The annual amount cancels, so
  the CV is a deterministic function of (yatra_income_share, yatra_months) ONLY. Asking a
  typical season / off-season month adds nothing the share does not already carry -- the
  user is right. Consequence: with the calendar gone every respondent takes the fallback,
  so (a) income_from_fallback becomes constant and leaves the covariate vectors, and
  (b) income_seasonality_cv is a transform of yatra_income_share_r, which is in the SAME
  Exposure vector in all three VEP arms -- so it leaves the vectors too and is retained as
  a descriptive only. Relevance to the four analyses: MPI and VMPI do not use it at all
  (Alkire-Foster scores take no income covariates); VEP and employment-VEP used it only as
  one Exposure covariate. No headline rate depends on it.
- **CPR block** — foraging is banned by the Forest Department on the Hemkund side and
  evidently tolerated on the Kedarnath side, so No/Yes/Don't know conflates "we do not"
  with "we are not permitted to". Fix: new `cpr_permitted` establishes the de jure
  baseline in one question, the four use items gain code 2 "No -- not allowed here", the
  whole block becomes optional, and the module gets the intro it never had, including a
  line that answers are confidential and go to no department. Asking a person to admit
  unauthorised collection to a stranger with a tablet is both a validity and a safety
  problem; the prohibition code is what removes the need to.
